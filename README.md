# تقنية تُنصت.. وأمل يتجدد

موقع عربي RTL خفيف لنادي قوقل للمطورين بجامعة الطائف. يعمل دون إطار عمل أو API. الخطوط والشعار المرفقان مضمّنان دون تعديل ألوان الشعار أو نسبته.

## التشغيل

ثبّت Node.js إصدار 20 أو أحدث، ثم افتح الطرفية داخل هذا المجلد:

```sh
npm start
```

افتح http://127.0.0.1:4173. لا تفتح index.html مباشرة عبر file://؛ تستخدم الملفات JavaScript Modules. التشغيل لا يحتاج npm install. تحتاج `npm ci` فقط لتوليد QR. الاختبارات: `npm test`.

## التخصيص

- استبدل `dist/assets/logo.png` بشعارك؛ خاصية height:auto تحفظ النسبة. يظهر الشعار نفسه في الترويسة والتذييل والجدار والإشراف وبطاقة التعلّم. حُذفت نسخة الترحيب المشوهة. في الداكن يوضع على خلفية بيضاء دون تغيير ألوانه.
- الخطوط في `dist/assets/fonts/`. لتغيير الأسماء عدّل قواعد @font-face في styles.css. الأوزان 300 و400 و500 و700 و900. لا يُحمّل أي خط خارجي.
- عدّل `dist/js/config.js`: hero، cards، ui، metrics، scenarios، replies، suggestions، support، seeds، club، team وsocial. بيانات المواقف منفصلة عن منطق التشغيل؛ أضف موقفًا بثلاثة خيارات وثلاثة آثار لكل خيار وفهرس best ومهارة skill. بعض تسميات عناصر الواجهة القصيرة موجودة في app.js ويمكن نقلها إلى ui عند إضافة ترجمة.
- ضع أسماء الفريق الحقيقية في team. ضع الحسابات الموثوقة فقط في social كمصفوفة `{title, url}`. لم تُخترع أسماء أو حسابات.
- النتائج والمؤشرات رمزية تعليمية، وليست تقييمًا طبيًا. بطاقة النهاية PNG تُحمّل على جهاز الزائر ولا تُرسل خارجيًا.

## الكشك والخصوصية

زر وضع الكشك في التذييل يطلب ملء الشاشة ويبدأ إعادة الجلسة بعد 60 ثانية بلا نشاط. يُصفّر المحاكاة والمحادثة والمسودة، ويعيد الصفحة للأعلى، مع الاحتفاظ برسائل الجدار للمراجعة. يمكن تعديل المدة في config.kioskSeconds. لوحة الإشراف تقفل تلقائيًا بعد الخمول. وضع /wall لا يعود للصفحة الرئيسية كي يستمر العرض.

الأزرار مناسبة للمس، والتحديد معطل في وضع الكشك خارج الحقول. touch-action:manipulation يمنع تكبير النقر المزدوج مع إبقاء التكبير بالإصبع لإمكانية الوصول. لبوث غير مراقب استخدم وضع الكشك في نظام التشغيل لتقييد الخروج؛ صفحة الويب وحدها لا تقفل الجهاز. يدعم reduced-motion ولوحة المفاتيح والوضع الداكن. الإنجليزية غير مضافة في هذه النسخة؛ يمكن إضافة قاموس en مع تغيير lang وdir لاحقًا.

لا توجد تحليلات أو إرسال للمحادثة أو حفظ للقرارات. الرسائل محلية على المتصفح، بلا أسماء. لا يمكن ضمان اكتشاف كل معلومة شخصية تلقائيًا، لذلك **كل الرسائل تمر بمراجعة بشرية**.

## الإشراف المحلي: حدود مهمة

افتح /admin/ على جهاز المنظم. في أول مرة، أنشئ كلمة مرور من 10 أحرف على الأقل. تُخزن بصمة PBKDF2 مع salt، ولا تُخزن كلمة المرور كنص. راجع الرسائل ثم وافق أو احذف. افتح /wall/ في تبويب آخر في المتصفح نفسه؛ تتحدث الرسائل مباشرة عبر storage events.

هذا قفل واجهة محلي **وليس حماية إنتاجية**: من يستطيع تعديل localStorage أو JavaScript يمكنه تجاوزه، كما أن إعداد كلمة المرور الأول متاح لمن يفتح الصفحة أولًا. جهّز جهاز البوث قبل الزوار. بيانات المتصفحات والأجهزة لا تتشارك؛ رسالة من هاتف لن تظهر على شاشة البوث بهذه النسخة. لا تستخدم هذه اللوحة وحدها لجدار عام متعدد الأجهزة. عند تلف/امتلاء التخزين تظهر رسالة فشل ولا يُدّعى نجاح الحفظ.

## ربط Firebase / Firestore

1. أنشئ مشروع Firebase وقاعدة Firestore، وفعّل Firebase Authentication للمنظمين فقط. أضف App Check وحدود معدل من جهة الخادم.
2. أنشئ مجموعة `messages`: id, text, color, icon, status, createdAt. يجب أن يفرض الخادم status=pending؛ لا يثق بالحالة المرسلة من المتصفح.
3. استبدل محوّل storage.js بنفس الواجهات list/submit/moderate/subscribe. `submit` يستدعي Cloud Function تتحقق من الطول والفلترة والمعدل، و`moderate` يستدعي دالة تتطلب رمز دخول وادعاء admin مُنشأ من خادم موثوق.
4. استعلم للزوار عن status=approved فقط، وللإداري عن قائمة المراجعة. استخدم onSnapshot في subscribe لتحديث شاشة الجدار، واحذف مستمعيه عند مغادرة الصفحة.
5. في قواعد Firestore، امنع كتابة الزائر المباشرة، واقصر قراءة pending وتعديل/حذف السجلات على admin. لا تمنح صلاحية admin من الواجهة. اختبر القواعد بمحاكي Firebase قبل النشر.
6. أضف سياسة مدة احتفاظ وحذف، وحدّث نص الخصوصية ليصرّح بإرسال الرسالة إلى الخادم. حذف الرسائل بعد الفعالية خيار مناسب.

## رفيق الأمل

النسخة الحالية Rule-based ومعلنة كذلك في الواجهة. getAIResponse في ai.js هي نقطة الربط المستقبلية. systemPrompt في config.js. للربط الحقيقي أنشئ endpoint على خادمك وأبقِ مفتاح API في أسرار الخادم؛ طبّق فحص الأزمات والمحتوى والمهل وحدود المعدل على الخادم أيضًا. الفلترة بالكلمات لا تضمن اكتشاف كل أزمة أو لهجة. لا تجعل هذه المحادثة أداة فرز سريري أو خدمة طوارئ.

## النشر المجاني

لا توجد خطوة build. مجلد النشر هو **dist** فقط. تختلف حدود الخطط المجانية بمرور الوقت.

- GitHub Pages: ارفع محتويات dist إلى جذر مستودع ثم فعّل Pages من فرع main وجذر /. المسارات نسبية لتعمل تحت اسم مستودع. لا ترفع node_modules. وثائق: https://docs.github.com/en/pages/quickstart
- Netlify: ارفع مجلد dist من واجهة النشر اليدوي أو اربط المستودع واجعل Publish directory=dist وBuild command فارغًا. https://docs.netlify.com/deploy/create-deploys/
- Firebase Hosting: ثبّت Firebase CLI الرسمي، سجّل الدخول، نفّذ firebase init hosting واختر dist، ولا تستبدل index.html، ولا تستخدم SPA rewrite لأن صفحات wall وadmin موجودة. ثم firebase deploy --only hosting. https://firebase.google.com/docs/hosting/quickstart

نسخة Sites الأولية خاصة بمالكها؛ ليست رابطًا عامًا لجوالات الزوار. انشر dist على استضافة عامة وفق الخطوات أعلاه قبل طباعة QR، وأضف التخزين الخلفي إذا أردت استقبال رسائل الهواتف على شاشة الجدار.

## QR

الرمز المرفق يعمل لكنه يشير إلى رابط معاينة Sites الخاصة، ومُعلّم بذلك في التذييل. بعد النشر العام:

```sh
npm ci
node scripts/qr.mjs https://your-public-site.example
```

أعد نشر dist بعد التوليد، وغيّر وصف المعاينة الخاصة في التذييل إلى وصف رابطك العام. SVG يحوي مساحة بيضاء حول الرمز. اختبر مسحه من جهاز غير مسجّل الدخول قبل الطباعة. لا تستخدم localhost داخل رمز مخصص للزوار.

## تحسينات لاحقة

مصادقة وخادم إشراف حقيقيان، تخزين مشترك للهواتف، ترجمة إنجليزية كاملة، اختبارات وصول بأجهزة فعلية، مراجعة مختص للمحتوى، ثم ربط نموذج لغوي عبر خادم بضوابط سلامة وخصوصية واضحة.

## التحقق

اختبارات Node تغطي اكتمال المواقف، أولوية رد الأزمة، حجب الطلبات غير الآمنة، توجيه الردود، فلترة الرسائل، ومراحل التخزين والمراجعة. فحص بناء JavaScript وHTTP للصفحات والأصول. الفحص البصري والتفاعل داخل المتصفح لم يكتمل بسبب رفض بوابة صلاحيات المتصفح فتح localhost؛ يلزم فحص فعلي على الهاتف وشاشة البوث قبل الاستخدام.
